# Phase 0: Repository Recovery

## Goal

Turn the current sync-conflicted working directory into one reviewable, versioned source tree without
losing newer work. This phase changes no product behavior deliberately.

## Why this phase is separate

The canonical filenames and their `federate-safeBackup` counterparts represent different development
generations. Tests, UI modules, package metadata, and the CLI currently reference APIs from both. A
feature agent cannot reliably infer which side of an error is stale. Recovery therefore requires
careful comparison and owner-visible evidence, not opportunistic bug fixes.

## Work package 0A — Preserve and inventory

Recommended executor: a careful agent with Git competence.

Tasks:

1. Record the current branch, commit, `git status --short`, and checksums for every backup/canonical
   pair in a recovery report.
2. Create a recoverable snapshot (branch or commit) containing all current work. Do not delete or
   rename anything before the snapshot is verifiably addressable.
3. Classify every `federate-safeBackup` path as identical, newer candidate, older candidate, or
   unique/no counterpart. Use content and cross-file API compatibility, not timestamps alone.
4. Identify generated artifacts (`__pycache__`, egg-info, pytest caches, session/index data) separately
   from authored source.

Acceptance criteria:

- The recovery report lists all 58 backup paths and the disposition proposed for each.
- A Git reference preserves every current authored file.
- No current work is deleted during this package.

## Work package 0B — Select a coherent generation

Tasks:

1. Recover related files as compatibility clusters, not isolated newest-file wins. At minimum treat
   these as clusters:
   - CLI/config/agent construction/package entry point;
   - ReAct loop/planner/prompts/retry/scratchpad/UI protocol;
   - Textual/streaming/REPL UIs and their tests;
   - diff store/undo/redo/edit/refactor tools and their tests;
   - symbol index/dependencies/retrievers/watcher and their tests;
   - RAG/chunker/store/embeddings and optional dependency metadata.
2. For each cluster, choose the version whose public APIs satisfy its associated tests. Preserve useful
   changes from the other version explicitly through a merge, rather than overwriting silently.
3. Ensure `pyproject.toml` points at the selected real entry function and contains dependencies used by
   default code paths (the newer TUI requires Textual).
4. Remove conflict suffixes from imports and test discovery. Keep any archival copies outside the
   package/test discovery paths if the owner wants them retained.

Acceptance criteria:

- `rg --files | rg 'federate-safeBackup'` returns no product or test files.
- `python -m chef_human.main --help` exposes exactly the intended commands.
- Importing every default CLI/UI module succeeds in a Python 3.12/3.13 environment.
- The package entry point and `python -m` entry point produce the same command tree.

## Work package 0C — Repository hygiene

Tasks:

1. Stop tracking generated bytecode and package metadata; extend `.gitignore` only where needed.
2. Decide which historical `plan_*.md`, `output.txt`, editor metadata, and local session data belong in
   the public repository. Archive valuable history under one directory; remove incidental artifacts
   from the public branch.
3. Add a brief `RECOVERY.md` recording what was reconciled and which snapshot retains the raw state.
4. Commit recovery separately from functional fixes so reviewers can understand the transition.

Acceptance criteria:

- `git status --short` is empty after the recovery commit.
- Running tests does not create tracked changes.
- Root-level files each serve a clear public purpose.

## Agent constraints

- Never bulk-copy every backup over its counterpart.
- Never delete untracked files before the preservation snapshot and inventory are complete.
- Do not fix behavioral bugs in the recovery commit unless required to resolve an API-generation
  choice; record those bugs for Phase 1.
- Report ambiguous pairs to the owner with a short diff summary and recommendation.
